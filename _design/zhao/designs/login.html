Operator Access
运营智能体 ECOMMERCE OPERATIONS AGENT

统一运营 Agent 中心的唯一公开入口。登录后由一个协调 Agent 从版本化工作流中路由， R2 / R3 副作用必须经数据库审批放行，业务结果回到可编辑工作台。

本页安全边界
  • 页面不渲染任何账号、口令或口令片段；演示凭据一律向管理员线下获取。
  • 密码字段 type=password，不回显、不进入前端状态、不写入日志。
  • 失败提示不区分「邮箱不存在」与「密码错误」，避免账号枚举。
  • 令牌只落在 httpOnly + SameSite=Lax Cookie 上，前端脚本读不到。
认证链路
  1. POST /login/submit表单提交（Next.js route handler）
  2. POST /api/v1/auth/login转发给 FastAPI，返回 access_token
  3. Set-Cookie · httpOnlySameSite=Lax · Path=/ · 服务端统一附加 Authorization
  4. 302 → /进入业务工作台

Fix · 05

关闭浏览器原生气泡（novalidate），改用可定位字段的自定义提示；错误文案挂在 aria-describedby 上，屏幕阅读器能读到。

登录状态已过期，请重新登录

原会话已被服务端判定失效，本次操作未提交，重新登录后可继续。

Branch · expired

Agent 中心在 401 时跳 /login?expired=1，但线上登录页只读取 error 参数，这条提示被丢弃 —— 本稿补上该分支。

账号已停用

凭据正确但账号状态为停用，无法进入工作台。请联系管理员恢复账号或改用其他成员账号。

Branch · disabled

线上 /login/submit 把任何非 2xx 都归为 ?error=1，无法区分停用与密码错误；落地需后端返回可区分错误码（如 403 account_disabled）。

线上原版 本稿处理 为什么
以 emerald 成功色区块明文渲染 owner 测试账号与密码，并加 select-all 方便复制 整块删除，替换为中性的「演示凭据 · 请向管理员获取」说明；全页不含任何账号或口令 任何拿到该 IP 的人都能直接登录 owner；口令还会进入截图、录屏、浏览器缓存与搜索引擎快照
失败只有一句「邮箱或密码不正确，或者账号已停用。」 拆为四类：本地字段校验 / 服务端凭据错误（字段级标注 + 自查清单）/ 会话过期 / 账号停用 用户无法定位问题；同时仍不通过「邮箱是否存在」泄露账号信息
无提交中态，按钮可反复点击 提交中态：禁用输入与按钮、表单 aria-busy、按钮内状态灯、认证链路进度 重复提交会反复打登录接口；用户无法判断请求是否已发出
