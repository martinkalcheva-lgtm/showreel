# 全套 UI 设计稿 · 前端交接文档

> **这是什么**：4 套线上系统 + 1 个作品集首页的**重新设计稿**——共 12 个设计页（另含 designs\ 下总览 index.html 1 个，与总览页自述口径一致）+ 1 个作品集首页（仓库根 index.html）；designs\ 内 15 个文件（13 页 + design-system.css + icons.js），全包共 14 个 HTML。
> **这不是什么**：不是可直接上线的生产代码，不是后端改动方案。
> **交接给谁**：负责把这套设计落到线上系统里的前端工程师。

---

## 0. 一句话说清这次要做什么

线上那 4 套系统是不同时期、不同技术栈、不同人做的，视觉上**只有色值勉强统一，组件层面全面发散**（圆角有 6/10/12 三种，控件高度 30/36/40 三种，只有 1 个系统有暗色模式）。

这次的目标不是"换个皮"，而是：

1. **建立一套共享设计系统**，designs\ 内全部页面（12 个设计页 + 总览 index.html）只能消费它的 token，不许自定义颜色/圆角/阴影/字体；
2. **每页顺手修掉一个真实缺陷**（见 §4 的逐页对照表），这些缺陷是勘察线上系统时实测出来的，不是主观审美问题。

#### `--accent` 与 `--accent-solid` 的分工

一个 accent token 想同时当「实心按钮底」和「文字/边框」是无解的：

- 当底要够暗才配得上近白字
- 当文字要够亮才压得住深色 tint 底

**浅色档** `--accent` 与 `--accent-solid` 恰好同值（48%），因为 48% 这个亮度两头都够：白字 6.9:1 / 对 tint 底 6.1:1。

**深色档**必须拆成两个 token：
- `--accent`（70%）：文字/边框/图标用，对最亮的深色底实测 >=5.5:1
- `--accent-solid`（57%）：实心按钮底，配 `--on-accent` 近白字 4.71:1（>=4.5）

hover 只比 rest 亮 5 档（62%）而不是原来的 7 档——白字对比随底色变亮衰减极快（72% 时只剩 2.59:1；该组合未被使用，本句为解释性文字），5 档是「看得出悬停」与「字还认得清（3.81:1）」的平衡点。

#### 墨色层级阶梯

浅色档 18/32/41/51，深色档 93.5/82/74/67，每档 >=9~10 L：

| 层级 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--fg` | 18% | 93.5% | 正文/标题 |
| `--fg-secondary` | 32% | 82% | 导语 |
| `--muted` | 41% | 74% | 次要说明 |
| `--faint` | 51% | 67% | 标签/时间戳 |

**>=4.5，最低 4.72**（深色按钮 hover 态对比 3.81，瞬时态，基础态 4.72）。

### 2.4 硬性规则（违反即返工）

1. **不许写死颜色**。只能用 `var(--...)`。禁止 `#xxx` / `rgb()` / `rgba()`。
2. **不许写死圆角**。只能 `var(--radius)`（=2px）。禁止胶囊按钮、圆形头像。
3. **不许加投影**。`box-shadow` 只允许 `none`。层级靠边框和底色区分。
4. **不许用渐变 / 发光 / 毛玻璃**。禁止 `linear-gradient`、`backdrop-filter`、`filter: blur()`。
5. **中文标题不许负字距**。汉字墨迹占 em 框 88-94%，负字距会让笔画相撞。
6. **字号下限**：正文 >=16px，次要文本 >=15px，等宽小标签 >=13px。低于此值在投影仪上必糊。
7. **不许用 emoji 当图标**。
8. **不许引入图标库**。用 `icons.js` 注入的 13 枚图标。

### 2.5 新地基规则

- `.tbl` 在 <=767 有防塌缩兜底：`width:max-content;min-width:100%;max-width:60rem`
- `.tbl-note` 有地基标准版：说明文字放滚动容器外，不许当 caption 放容器内
- `.rail` <=899 有右缘渐隐提示：**功能性 mask 豁免**，不是装饰渐变
- `.app-top .brand` 命中区 44px：`::after` +/-8px 技巧
- `.btn-sm` 44px、顶栏导航 44px
- 输入控件（`input` / `select`，类名 `.input`）高 44px（design-system.css:390；初版为 42px，已在 CSS 层修复，login / agent / product-detail 三页原有的局部 `min-height:44px` 与地基同值）

### 2.7 图标

`icons.js` 会把 13 枚图标注入为一个 `<svg>` sprite，用 `<use>` 引用：

```html
<svg class="ic"><use href="#i-ext"></use></svg>
<svg class="ic ic-lg"><use href="#i-arrow-r"></use></svg>
```

可用 id：`i-ext`（外链）`i-arrow-r`（右箭头）`i-chev`（展开）`i-copy`（复制）`i-repo`（代码仓库）`i-server`（服务器）`i-db`（数据库）`i-search`（向量检索）`i-agent`（智能体节点）`i-terminal`（终端）`i-doc`（文档）`i-check`（勾选）`i-warn`（警告）

规格：24 网格 / 描边统一 `1.5` / `round` 端点 / `currentColor`。
**不要单独调某个图标的线宽**——并排时线宽不一致比尺寸不一致更刺眼。

品牌标志：`icons.js` 导出 `window.OD.MARK`（SVG 字符串）和 `window.OD.FAVICON`（data URI）。

### 2.8 响应式断点

| 断点 | 覆盖 |
|---|---|
| `>=1280` | 笔记本 / 投屏主场景 |
| `1024-1279` | 投屏紧凑档 / iPad 横屏 |
| `<=899` | 主栏塌陷，左栏变横向滚动 |
| `<=767` | 手机，导航换行 |
| `<=479` | 窄屏 |
| `横屏 且 高<=500` | 手机横放 / 分屏 |

**平板档（768-899）顶栏为两行**：这是修复过的结构问题，不是缺陷。固定 60px 单行顶栏放不下「品牌 + 4-5 个中文导航项 + 操作区」，继续硬撑只会导致 flex 最小内容宽度把整页顶宽，或导航项折行顶穿顶栏。

**<=767 顶栏两行 + 导航横滑**：与平板档同套路，用 `min-height` 保住视觉底线。

**触摸端注意**：所有 `:hover` 效果必须包在 `@media (hover: hover) and (pointer: fine)` 里。
移动浏览器会把首次 tap 当作 hover 并**粘住**，不包的话手机上会出现残留高亮。

### 2.9 动效

只有 4 条缓动曲线，语义唯一，不许发明第五条：

```css
--ease-enter: cubic-bezier(0.05, 0.7, 0.1, 1);   /* 进入：快起步慢收尾 */
--ease-exit:  cubic-bezier(0.3, 0, 0.8, 0.15);    /* 离开：慢起步快飞走 */
--ease-state: cubic-bezier(0.2, 0, 0, 1);         /* 原地：hover/展开 */
--ease-loop:  cubic-bezier(0.45, 0.05, 0.55, 0.95); /* 循环：仅呼吸灯 */
```

**预算**：无限循环动画只限**状态指示**——状态灯 / 骨架屏 / 流式光标三类，一律用于表达"还在跑"，不作装饰动画。
**只动 `transform` / `opacity`**——动画 `box-shadow`、`width`、`height` 会触发重排重绘。
必须完整支持 `prefers-reduced-motion`。

**同一视口同时呼吸建议 <=8**，超出用 `animation-delay` 错峰（model-config 49 个已全部错峰实测）。
包内现状：`.status-led`（design-system.css）、`.trace-dot.run`（design-system.css）、页面本地 `.sk` 骨架（research / kb-chat / model-config）均属"状态指示"这一类，已实测全部错峰。**"全站只许 1 处"是旧口径，作废**——骨架屏和流式光标同属状态指示，按上面三条判。

## 3. 各技术栈怎么接入这套设计系统

这是落地时最大的障碍：4 套系统技术栈完全不同。**设计系统是纯 CSS + 少量原生 JS，不带框架，所以四端都能用，但接入方式不一样。**

### 3.1 7954 知识库智能体（FastAPI + 原生 HTML/JS，无框架）

**最简单的一档。** 现成资料：`/chat.html`、`/import.html`，都是单文件内联 CSS。

做法：
1. 把 `design-system.css` 和 `icons.js` 放进静态资源目录；
2. 两个页面各加一行 `<link rel="stylesheet" href="/static/design-system.css">` 和 `<script src="/static/icons.js"></script>`；
3. **删掉页面内原有的 `:root` 变量块**（原有一套 `--c-brand`/`--c-ink` 等，与新系统冲突）；
4. 按设计稿重写 DOM 结构，套 `.app` / `.rail` / `.msg` / `.cite` 等类；
5. 原有的 SSE 流式逻辑、上传逻辑**保持不动**，只换 DOM 和样式。

### 3.2 8000 联网调研 / 18082 智能应答台（Vue 3 + Vite）

做法：
1. 在 `main.js` 里 `import './styles/design-system.css'`（放在所有组件样式之前）；
2. `icons.js` 是 IIFE，在 `index.html` 里用 `<script src="/icons.js"></script>` 引入，或在 `main.js` 里 import；
3. **不要试图把设计系统改写成 Vue 组件**。它是纯 CSS 类，直接写在 template 的 `class` 上即可；
4. 原有的状态管理、WebSocket / API 调用**保持不动**。

注意：这两个是 SPA 单屏应用，**没有 vue-router**。设计稿里的"左栏会话列表 / 右栏文件面板"是靠 `v-if` 控制的面板开关，不是路由。别照着设计稿去加路由。

### 3.3 80 运营工作台（Next.js 16 + App Router + Tailwind 4）

**最麻烦的一档**，因为 Tailwind 和这套 CSS 变量体系是两套东西。

8 个页面都在 `web/src/app/` 下：
- `/login` - 登录页
- `/agent` - Agent 中心
- `/products/[id]` - 单品运营
- `/stores/[id]` - 店铺详情
- `/products/[id]/generation-jobs/[jobId]` - 生成任务
- `/imports` - 导入中心
- `/settings` - 模型配置
- `/` - 运营工作台首页

**设计稿的 `.tbl`/`.kpi`/`.trace` 等类名与 Tailwind 类共存时的优先级说明**：
设计系统用 CSS 类定义组件样式，Tailwind 用工具类定义原子样式。两者共存时，**后加载的样式表覆盖先加载的**。推荐在 `globals.css` 中先 `@import` 设计系统，再引入 Tailwind，这样 Tailwind 工具类可以覆盖设计系统的组件类（如需微调）。但**不要混用两套颜色系统**——要么全用设计 token，要么全用 Tailwind 色阶。

推荐做法（二选一）：

**方案 A（推荐，改动小）**：把设计 token 映射进 Tailwind theme，然后**在新页面里只用工具类**。
```css
/* app/globals.css */
@theme {
  --color-bg: oklch(97.6% 0.004 85);
  --color-surface: oklch(99.3% 0.002 85);
  --color-fg: oklch(18% 0.014 250);
  --color-accent: oklch(48% 0.165 28);
  --color-success: oklch(46% 0.135 152);
  --radius-base: 2px;
}
```
之后用 `bg-bg` / `text-fg` / `border-accent` / `rounded-base`。

**方案 B（改动更小但不够干净）**：`globals.css` 里 `@import` 设计系统，页面里混用 `class="panel"` 和 Tailwind 工具类。

### 3.4 18082 智能应答台（Vue 3 + Vite）

同 3.2，注意 SPA 单屏应用无路由。

## 6. 常见误解（提前说清）

| 误解 | 事实 |
|---|---|
| "这是要替换线上系统的成品代码" | 不是。这是**设计稿**，DOM 是静态的，接口调用要你自己接回原系统 |
| "设计稿是响应式的，所以线上也是" | 设计稿的响应式是真的（已实测 52 组零溢出 = 13 设计页 × 1440/390 × 明/暗，另有六档宽度 375/390/414/768/1024/1440 + 横屏矮窗 800×400），但**线上要你自己实现**，别指望拷过去就自适应 |
| "配色跟线上不一样，是不是错了" | 线上 4 套系统共用的 `#f4f6fb` + `#1d4ed8` 是 **Tailwind 官方色阶的原值**，属于最常见的"AI 生成感"来源。新配色是刻意的 |
| "为什么圆角只有 2px，太硬了" | 这是"印刷技术规格书"这个视觉方向的核心决策。圆角越大越像通用 SaaS 模板 |
| "能不能加个渐变/发光让它更好看" | 不能。加了就退回原来那套观感了 |
| "设计稿里图片为什么是占位框" | 零外部依赖约束下不引图片，用 `.thumb` 标注块（IMG 1024x1024 / VID 720p 15s）；真实实现是 `<img object-contain>` / `<video controls>` |

## 7. 需要对接的技术细节

设计稿里的数据是**静态示例数据**，接真实接口时对应关系：

### 7.1 后端有字段但原前端从没渲染（开发时应补）

| 字段 | 来源 | 说明 |
|---|---|---|
| 任务耗时 `finished_at - created_at` | AgentTask | 原前端只显示状态，不显示耗时 |
| 审批决策理由 `note` | AgentApproval | 后端已有字段，reject 表单没接 |
| 过期时间 `expires_at` | AgentApproval | 审批过期时间未显示 |
| `catalog.coordinator` | 目录配置 | 协调 Agent 未渲染 |
| `workflow.agents` | 工作流配置 | 专家链未渲染 |
| `required_context_any` | 工作流配置 | 必需上下文未渲染 |
| `?section=` 锚点参数 | 前端路由 | 声明未用，锚点导航未实现 |
| `store.platform_accounts` | 店铺详情 | 授权过期=数据静默断流根因 |
| 账号状态 3 态 | platform_account | 正常/过期/未授权 |
| 库存流水 `InventoryMovement` | 库存明细 | 类型映射 inbound/outbound/adjustment/lock/release |

### 7.2 生成任务

供应商只返回离散态（如 `_jimeng_status` 的 done/failed），**没有 0-100 进度字段**——设计稿用 5 阶段轨迹+耗时轨道（30 分超时预算是调度器兜底值）+历史 P50/P90 参考值替代百分比，前端不要编造进度条百分比。

### 7.3 事件类型全集

8 种：`queued` / `started` / `succeeded` / `failed` / `retry_requested` / `retry_scheduled` / `cancelled` / `timeout_checked`

轮询 5 秒x120 次，仅在 pending/running 时启用。

### 7.4 失败重试

仅 failed 显示重试表单（POST /retry）；取消仅 pending/running（POST /cancel）。

### 7.5 已知权衡

- 深色按钮 hover 态对比 3.81（瞬时态，基础态 4.72）
- disabled 态（如 `opacity:.45` / `pointer-events:none` 的失效按钮）文本不参与 ≥4.5 静态扫描：WCAG 1.4.3 豁免非活动 UI 组件，已裁定
- **作品集首页 token 差异**：index.html（仓库根）与 design-system.css 现有 3 处 token 值不同——浅色档 `--muted` 45%≠41%、深色档 `--fg-secondary` 80%≠82%、深色档 `--muted` 67%≠74%（首页深色档最浅文字取的正是 design-system.css 中 `--faint` 的值）。首页为独立站点、token 独立维护（见 §1），另有独立修复在并行进行（深色 `--accent` / `--accent-hover` 已随该修复对齐 70% / 62%）；修完后此条如失效，由终验复核确认。
- **已知小项 · login.html 标题顺序**：`<h2>登录工作台</h2>`（第 225 行，正常态说明栏）出现在 `<h1>登录工作台</h1>`（第 287 行，登录卡）之前。该页有且仅有 1 个 h1、标题零跳级，大纲合法；首个可见标题为 h2 属风格选择（说明栏先于登录卡出现），不改动 HTML。
