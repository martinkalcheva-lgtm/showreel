01 · Knowledge & Data AI

问数与智库

智能知识库 / 数据问答系统

一句话说清楚：把“老板随口问的一个经营问题”，变成 11 个可观测节点 的标准处理流程，最后直接给出一句能拍板的结论。

  • LangGraph 组织问数流程：抽关键字 → 召回 → 过滤指标 → 生成 SQL → 校验 → 执行
  • SSE 实时推送节点进度，答案逐段返回，不再整页转圈等待
  • 结构化数据走 MySQL、向量召回走 Qdrant、关键词检索走 Elasticsearch，统一封装
  • 文件导入 + 知识库构建闭环，带答案来源回显

02 · Operations Agent

电商运营助手

运营场景智能体

一句话说清楚：把电商日常运营里重复、琐碎、要来回切换后台的活，变成 从建档到复盘的一条闭环流水线。

  • 单品运营闭环：建档/SKU → 竞品 → 诊断 → 素材 → 投放 → 数据 → 复盘
  • 商品与 SKU 库存流水登记，入库、锁定、预警分列，可回溯对账
  • 图片/视频生成放后台队列执行，页面自动刷新状态，不用守着
  • 统一模型配置入口，按能力切换模型与参数，业务侧无感

03 · Customer Service

智能客服系统

客服会话与话术管理系统

一句话说清楚：让客服不用记住所有订单细节，也能在对话里 实时带出客户和订单信息，话术随手取用。

  • 会话全生命周期管理：按 TURN 编号逐轮留痕，上下文可回溯
  • 会话与业务对象联动：右侧面板实时带出订单、商品、金额、发货状态
  • 话术库与智能推荐结合，一键取用，减少重复打字
  • 前端按设计稿重构应答台，顶栏服务探活，打印场景样式也覆盖了

我是怎么做事

先跑通，再打磨。我习惯从最短路径开始：一周内让真实流程走起来，用真实数据验证，界面只留必要的东西。

后端不将就。存储按场景选型，访问层统一封装；前端只做一件事：把能力说成人话，让业务方看得懂。
